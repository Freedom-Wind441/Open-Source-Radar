## 一、重点发现

### 1. Llama Windows：优先实际试用

它是基于 WinUI 3 的 Windows 11 托盘应用，管理本地 llama.cpp 推理服务，支持直接从 Hugging Face 搜索和下载 GGUF 模型。

除了图形界面，项目还提供 OpenAI-compatible API，可以让其他本地应用复用同一推理服务。仓库采用 MIT 许可证，提供安装包、源码构建说明和测试项目。[项目仓库](https://github.com/ggml-org/Llama-Windows)

值得特别关注的是 10 月 10 日发布的 v0.12.0：它加入了 Hugging Face 模型搜索、KV Cache 量化配置、并发模型数量限制，并修复了网络暴露、凭据存储和运行时更新方面的问题。[发布记录](https://github.com/ggml-org/Llama-Windows/releases)

**建议：** 可以在 Windows 主机上与现有 LM Studio 进行对照测试。重点比较模型加载时间、显存占用、API 兼容性和后台资源消耗，不必立即替换现有方案。

### 2. Granite Switch 4.1：优先研究架构

10 月 14 日发布的 8B 版本，将通用语言模型、Decision aLoRA、Guardian aLoRA 和英文语音识别编码器整合进同一模型服务。

不同能力可以通过控制标记按需激活，并共享基础模型的 KV Cache。它已经提供模型权重、部署示例、在线 Demo 和 Apache-2.0 许可证。[模型卡](https://huggingface.co/ibm-granite/granite-switch-4.1-8b)

这对软件架构研究有一个具体启发：**某些任务可以交给具有明确输入输出契约的专用适配器，而不必每次都调用完整的通用推理流程。**

但需要注意，官方也明确指出，其决策概率不能直接视为未经领域验证的可靠分类结果，英文语音识别仍存在误转写问题。

### 3. bobby-browser：值得研究的 Agent 执行层

这是一个基于 Rust 的浏览器自动化运行时，支持 Firefox、Chromium，以及 MCP、ACP、HTTP API 和多语言 SDK。

它的重点是权限限制、执行日志、证据记录、检查点和故障恢复。10 月 14 日的 v0.20.0 修复了大量跨 iframe、富文本输入、页面遮挡和浏览器会话恢复问题。[仓库](https://github.com/cavi-ai/bobby-browser) · [发布记录](https://github.com/cavi-ai/bobby-browser/releases/latest)

对你正在研究的软件行为验证而言，值得借鉴的是它如何把“执行动作”与“证明动作已经正确完成”联系起来。

目前仍为 Alpha，接口可能变化。项目采用 MIT 许可证，提供安装包、SDK 和测试说明，适合研究或隔离环境试用。

### 4. Reflection Beam：技术观察优先

10 月 16 日发布的 Beam 是一个 501B 总参数、每 Token 激活约 23B 参数的 MoE 模型，支持最长约 100 万 Token 的上下文，采用 Apache-2.0 许可证。

它提供模型权重、推理框架支持、训练示例和公开测试记录。不过，官方推荐的 NVFP4 部署仍需要约 280GB 权重存储空间及多卡服务器，远超普通 16GB 显存设备的能力。[发布文章](https://huggingface.co/blog/reflection-beam)

因此，它值得关注的是混合注意力、长上下文 KV Cache 控制和结构化工具调用，而不是在个人电脑上部署。

## 二、本期补充判断

**优先顺序：Llama Windows → Granite Switch 4.1 → bobby-browser → Reflection Beam。**

Llama Windows 最适合立即开展对照实验；Granite Switch 4.1 更适合研究模块化模型架构；bobby-browser 可作为 Agent 行为验证和故障恢复的设计参考；Beam 则暂时只值得跟踪其技术路线。

商业价值方面，四个项目均有实际应用场景，但本轮未找到足以确认其付费转化或持续盈利能力的公开证据。

本轮也没有筛选出同时满足近期性、可运行性和许可核查要求的金融量化新项目。
